1. **high — XSD→RE2 feasibility is understated (L74, L160).** Regularity makes translation possible in principle, not straightforward. Subtraction, XML name classes, Unicode blocks, anchoring and Go’s 1,000-repeat limit need explicit handling. Rejecting valid patterns contradicts full compliance. **Fix:** prototype an XSD parser plus character-set algebra; define supported limits before committing. [XSD](https://www.w3.org/TR/xmlschema-2/#regexs), [Go syntax](https://pkg.go.dev/regexp/syntax)

2. **high — “when with auto-delete semantics” is dangerously underspecified (L40).** Libyang deletes nodes whose previously satisfied condition becomes false; newly supplied false-`when` data normally fails validation. Choice replacement similarly depends on node history. **Fix:** represent validation history and test fresh-invalid versus valid→edit→invalid sequences. [Pinned implementation contract](https://github.com/CESNET/libyang/blob/v5.8.6/src/parser_data.h)

3. **high — NMDA is reduced to config/state filtering (L44–45).** Operational contains applied `config true` data as well as state, and need not satisfy all semantic constraints. Libyang’s operational mode reports semantic violations as warnings. **Fix:** specify datastore-specific validation, intended/running distinctions and origin inheritance; don’t merely permit `config false`. [RFC 8342](https://www.rfc-editor.org/rfc/rfc8342.html), [validation options](https://netopeer.liberouter.org/doc/libyang/master/html/group__datavalidationoptions.html)

4. **high — A generic Node interface does not establish XPath correctness (L75, L98).** `when` requires dummy-node/restricted-tree evaluation; grouping expressions retain definition-context namespaces. NMDA changes operation/state accessible trees. **Fix:** define explicit expression context, namespace bindings, accessible-tree views and dependency ordering before implementing the evaluator. [RFC 7950 §7.21.5](https://www.rfc-editor.org/rfc/rfc7950.html#section-7.21.5), [RFC 8342 §6.1](https://www.rfc-editor.org/rfc/rfc8342.html#section-6.1)

5. **high — Defaults are scheduled as an independent M3 feature (L35–36, L91).** Libyang adds/corrects implicit nodes during validation; they affect XPath and depend on conditions and choices. Explicitly supplied default-valued leaves need distinct provenance. `report-all-tagged` is missing. **Fix:** design defaults with validation and preserve provenance through edits, codecs and diffs. [Libyang defaults](https://github.com/CESNET/libyang/blob/v5.8.6/src/tree_data.h), [RFC 6243](https://www.rfc-editor.org/rfc/rfc6243)

6. **high — No partial-data contract (L39–45).** Filtered retrievals, RESTCONF subtrees and edit payloads cannot undergo complete-datastore mandatory/reference checks or automatic default insertion. **Fix:** expose separate parse, local-check and complete-validation operations, with subtree context and explicit unknown-node policies. [Libyang parsing modes](https://github.com/CESNET/libyang/blob/v5.8.6/src/parser_data.h)

7. **high — Operation validation lacks required inputs (L41).** RPC/action/notification references can require an external datastore; replies need operation identity, and nested actions require parent-instance context. **Fix:** specify request/reply kinds, dependency trees, source-request association and envelope handling in the API. [Libyang operation validation](https://netopeer.liberouter.org/doc/libyang/master/html/howto_data_validation.html)

8. **high — `anydata`/`anyxml` are absent from the tree design (L35–38).** These require payload representations beyond ordinary schema-bound nodes; arbitrary XML cannot always become RFC 7951 JSON losslessly. **Fix:** add typed/opaque payload variants, namespace preservation and explicit unsupported-conversion errors before M3. [RFC 7950 §§7.10–7.11](https://www.rfc-editor.org/rfc/rfc7950.html#section-7.10)

9. **high — Ordering and instance identity are unspecified (L35, L47).** User-ordered entries need moves; state lists can be keyless, and state leaf-lists may contain duplicates. A map keyed by value cannot represent these faithfully. **Fix:** define ordered instance storage, stable handles and move/diff behavior before codecs. [RFC 7950](https://www.rfc-editor.org/rfc/rfc7950.html)

10. **high — “Built-in types” hides a foundational value-model decision (L33–34).** JSON token kinds affect union selection; float64 loses integer/decimal64 precision. XML prefixes and JSON module names need different resolution. **Fix:** specify exact numeric storage, union-member identity and namespace-aware values before either codec. [RFC 7951 §6](https://www.rfc-editor.org/rfc/rfc7951.html#section-6)

11. **high — Context and YANG-library scope are incomplete (L29, L46, L59).** Imported versus implemented modules and multiple imported revisions matter. A Context alone cannot supply datastore mappings; clients also need library ingestion. **Fix:** model schema sets explicitly and support building contexts from advertised revisions/features/deviations. [Libyang Context](https://github.com/CESNET/libyang/blob/v5.8.6/src/context.h), [RFC 8525](https://www.rfc-editor.org/rfc/rfc8525.html)

12. **high — Protocol edits and libyang diffs need separate contracts (L37–38, L47).** Preserving `nc:operation` does not implement edit semantics. Libyang’s internal diff vocabulary is not NETCONF edits or YANG Patch, and diff trees may intentionally violate schema constraints. **Fix:** distinguish representations, validation policies and adapters; specify exactly what `ApplyDiff` accepts. [Libyang diff contract](https://github.com/CESNET/libyang/blob/v5.8.6/src/tree_data.h)

13. **med — `Diagnostic` is not a `ly_err_item` equivalent (L57–58).** It lacks severity, separate schema/data paths and source location; `AppTag` alone cannot supply protocol error classification/details. **Fix:** retain structured codes, warning severity, locations and constraint-specific parameters for NETCONF/RESTCONF adapters. [Pinned error structure](https://github.com/CESNET/libyang/blob/v5.8.6/src/log.h)

14. **high — M2 names the wrong oracle output (L90).** `yanglint -f yang` prints parsed schema; `-f info` selects compiled schema. Tree output omits constraints and cannot establish equivalence. **Fix:** use `info` for inspection and a versioned C-helper dump of relevant compiled-schema fields for comparison. [Format selection](https://github.com/CESNET/libyang/blob/v5.8.6/tools/lint/yl_opt.c)

15. **high — Yanglint cannot provide the whole proposed oracle interface (L93–106).** It has no general diff-output command or structured app-tag diagnostic stream; XPath output is node selection, not arbitrary typed evaluation results. **Fix:** build a small test-only C executable exposing schema, diagnostics, expression results and diff APIs. Production can remain cgo-free. [CLI source](https://github.com/CESNET/libyang/blob/v5.8.6/tools/lint/main_ni.c), [XPath command](https://github.com/CESNET/libyang/blob/v5.8.6/tools/lint/cmd_data.c)

16. **high — Oracle invocation policy is missing (L102–106).** In this version, yanglint’s default `data` mode enables operational semantics: invalid configuration constraints can produce warnings and success. **Fix:** record parser/validation modes, features, implementation sets and defaults per fixture; pin dependencies and build settings, not just a tag or rolling brew bottle. [Mode selection](https://github.com/CESNET/libyang/blob/v5.8.6/tools/lint/yl_opt.c)

17. **med — Byte equality conflates interoperability with printer imitation (L91, L94, L106).** JSON object order and escape spelling are not semantic; XML prefixes may differ equivalently. Over-normalizing can instead erase meaningful instance order. **Fix:** compare typed trees first, preserve sequence semantics, and maintain a separate exact-printer compatibility suite. [RFC 7951 §7](https://www.rfc-editor.org/rfc/rfc7951.html#section-7)

18. **high — Agreement percentage is not a conformance measure (L108–118).** Extracted fixtures lose C-test setup, options and mutation history; random generators can share the implementation’s blind spots. An allowlist alone does not establish normative correctness. **Fix:** maintain RFC requirement coverage, independent expected outcomes, YANG-version cases and stateful edit/default/diff properties.

19. **high — Milestones postpone architecture-breaking feedback (L89–96).** Defaults precede XPath/validation; XML arrives after the value model; parser acceptance is compared against a compiler’s rejection behavior. **Fix:** establish phase-specific tests, then build an early XML+JSON→typed tree→defaults→XPath→validation vertical slice before expanding schema coverage.

20. **med — BSD licensing rationale is wrong; “clean-room” is misleading (L122–135).** BSD-3 does not require the whole project to use BSD-3. Reimplementing behavior alone does not establish derivation; source translation warrants retained upstream notices. Reading source is not conventional clean-room development. **Fix:** describe a source-informed port, preserve applicable notices, and verify corpus redistribution rights individually. [BSD-3 terms](https://opensource.org/license/bsd-3-clause)

21. **high — Rejecting goyang conflates it with ygot (L21–23).** Goyang exposes parser/AST and resolved schema APIs; it is not inherently a generated-data runtime. Missing compiler semantics do not prove its parser is unusable. **Fix:** benchmark three options: contribute compiler fixes, reuse parser/AST with a new compiler/runtime, or rewrite. Treat “35–40%” as unsupported. [Goyang scope](https://github.com/openconfig/goyang#readme)

22. **high — Cambium evaluation happens after substantial sunk cost (L24, L158).** Its documented gaps broadly match the survey, but pure-Go deployment and differential conformance already exist; optional cgo outside the import closure does not defeat purity. **Fix:** evaluate collaboration/reuse before M1, using adversarial cases and maintainer compatibility—not waiting until M3. [Capabilities](https://github.com/signalbreak-labs/cambium#readme), [roadmap](https://github.com/signalbreak-labs/cambium/blob/main/docs/contributing/roadmap.md)

23. **high — The schedule has no credible estimation basis (L144–152).** A C-to-Go LOC multiplier omits external regex functionality and integration complexity. Twenty-six evening weeks budget roughly 80–100k implementation/test lines with almost no contingency. **Fix:** estimate engineering hours and uncertainty from completed vertical slices; make full parity a staged roadmap, not a six-month promise.

24. **med — Public extensibility is premature (L63–75).** Public `TypeHandler`, `ExtensionHandler` and generic XPath interfaces freeze contracts before deferred references, canonicalization and validation lifecycles are understood. **Fix:** keep implementations internal initially; implement required built-ins concretely and extract interfaces from demonstrated consumers.

25. **high — Hardening is deferred until release preparation (L96).** Untrusted schemas/data can exhaust resources through nesting, expansion, regex compilation and XPath evaluation despite Go’s memory safety. **Fix:** introduce input/expansion/work budgets, cancellation and fuzzing from M1; test hostile inputs throughout, with M8 reserved for release qualification.
