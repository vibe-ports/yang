# 0003 — XSD regular expressions (YANG `pattern`) on Go RE2

Status: accepted (M0 prototype), 2026-09-30. Code: `internal/xsdre`. Addresses review item 1.

## Context

RFC 7950 §9.4.5 defines `pattern` as an XML Schema regular expression (XSD Part 2, Appendix F).
Go's `regexp` is RE2, whose syntax and several semantics differ (Perl-style `\w \s \d`, `.`,
`^`/`$` are anchors, no class subtraction, no `\i \c`, no Unicode blocks, repeat limit 1000).
libyang v5.8.6 (`ly_common.c: ly_pat_compile_xmlschema`) does *not* translate: it escapes
`^`/`$` outside brackets, substitutes `\p{IsX}` by a hard-coded BMP range table, and hands the
rest to PCRE2 (`UTF|UCP|ANCHORED|ENDANCHORED`). It therefore inherits Perl semantics wherever
XSD and Perl disagree.

## Decision

1. **Own parser, no string rewriting.** `Compile` parses the XSD grammar (productions [1]–[37])
   into a small AST: set-of-code-points, concat, alternation, repeat.
2. **Character classes are exact range sets** (`charSet`: sorted inclusive rune ranges) with
   union / complement / intersection / subtraction. `[a-z-[aeiou-[e]]]`, `[^…-[…]]`, multi-char
   and category escapes inside classes are all evaluated as set algebra before emission.
3. **Emission** to an RE2 string: every class becomes explicit `\x{..}` ranges (so Go's own
   `\p` tables and Perl classes are never used), groups become `(?:…)`, the whole pattern is
   wrapped as `\A(?:…)\z` (XSD regexes are implicitly anchored; `^` and `$` are ordinary chars).
4. **Never approximate.** A valid XSD pattern Go cannot represent returns `*Error` with
   `Kind == ErrUnsupported` and a reason; invalid XSD returns `Kind == ErrSyntax`.
   `errors.Is(err, xsdre.ErrUnsupported)` works.
5. **XSD semantics over libyang quirks.** Where libyang's PCRE2 behaviour differs from XSD, we
   follow XSD; each difference below is a candidate for `conformance/deviations.md`.

API: `Compile(pattern) (*Pattern, error)`, `(*Pattern).Match(string) bool`, `String()`.
`modifier invert-match` is the caller's job (negate `Match`). `Match` returns false on invalid
UTF-8 (libyang/PCRE2 also fails such input).

## Supported set

| Construct | Definition used |
|---|---|
| Branches, empty branches, groups `( )`, `? * + {n} {n,} {n,m}` | XSD §F; `n <= m` enforced |
| `.` | any char except `\n`, `\r` |
| Single-char escapes | `\n \r \t \\ \| \. \? \* \+ \( \) \{ \} \- \[ \] \^` (exactly XSD's list; `\$`, `\/`, `\b`, `\1` are errors) |
| `\s` / `\S` | `[#x20 #x9 #xA #xD]` (not Unicode whitespace) |
| `\d` / `\D` | `\p{Nd}` |
| `\w` / `\W` | `[#x0000-#x10FFFF]-[\p{P}\p{Z}\p{C}]` — so `_` is *not* a word char, `€`/`+` are; `\p{C}` includes Cn (unassigned) |
| `\i` / `\c` (+ complements) | XML 1.0 **Fifth Edition** `NameStartChar` [4] / `NameChar` [4a] — see limits |
| `\p{X}` / `\P{X}` | general categories L Lu Ll Lt Lm Lo M Mn Mc Me N Nd Nl No P Pc Pd Ps Pe Pi Pf Po Z Zs Zl Zp S Sm Sc Sk So C Cc Cf Co Cn (+ Cs) |
| `\p{IsX}` / `\P{IsX}` | Unicode **15.0.0** `Blocks.txt`, name = block name with spaces removed, case-sensitive; all 327 blocks incl. supplementary planes |
| Classes | `[...]`, `[^...]`, ranges, subtraction `-[...]` (nested, must be last), `-` literal only first/last |
| `{` `}` | metacharacters: literal only when escaped (XSD 1.1 `NormalChar`; XSD 1.0 §F lists them as metachars) |

Unicode version: the block table `blocks_table.go` is generated by `go generate` (`gen_blocks.go`
downloads `https://www.unicode.org/Public/<unicode.Version>/ucd/Blocks.txt`), so blocks and
categories come from the same edition as Go's `unicode` package (15.0.0 for Go 1.25/1.26).
`TestUnicodeVersion` fails if a toolchain upgrade moves `unicode.Version` without regenerating.
Go's `unicode.C` already contains unassigned code points; `Cn` is derived as `C − Cc − Cf − Co − Cs`,
and a test checks the seven major categories partition the code space.

XSD 1.0 block names renamed by later Unicode versions are kept as aliases: `IsGreek` →
Greek and Coptic, `IsCombiningMarksforSymbols` → Combining Diacritical Marks for Symbols,
`IsPrivateUse` → the three private-use blocks (E000–F8FF, F0000–FFFFF, 100000–10FFFF). Every block
name in the XSD 1.0 §F.1.1 table resolves (`TestXSD10BlockNames`).

## Declared limits

| Limit | Reason |
|---|---|
| Repeat bound > 1000 (`a{1001}`, `a{0,1001}`) → `ErrUnsupported` | Go `regexp/syntax` hard limit; expanding by hand would be an approximation of program size, not semantics, and is refused on principle |
| Nested repeat product > 1000 (`(a{100}){100}`), parse-tree height, program size → `ErrUnsupported` | Go's `ErrInvalidRepeatSize` / `ErrNestingDepth` / `ErrLarge`, mapped with the Go code in the reason |
| Group / class nesting > 1000 → `ErrUnsupported` | bounds our recursive parser (budget, review item 25) |
| `\i` `\c` use XML 1.0 5th ed. | XSD 1.0 2nd ed. formally points at XML 1.0 2nd ed. `Letter`/`NameChar` (Appendix B tables, Unicode 2.0). 5th-ed. productions are the ones XSD 1.1 uses, are range-simple, and a superset for modern text. libyang rejects `\i`/`\c` outright, so no compatibility is lost |
| Block ranges follow Unicode 15.0, not Unicode 3.1 | e.g. `IsCJKUnifiedIdeographsExtensionA` ends at 4DBF (libyang: 4DB5); `IsSpecials` is FFF0–FFFF (XSD 1.0 also listed FEFF) |
| Surrogate code points never match | not representable in valid UTF-8; classes like `\p{Cs}`/`\p{IsHighSurrogates}` compile to an empty set |
| Compile cost | classes are materialised per escape (`\w` ≈ 700 ranges); 500×`\w` compiles in ~75 ms. A pattern-length budget belongs in the M1 resource budgets |

## Differential results vs libyang 5.8.6 (yanglint, PCRE2 10.47)

Harness: `go test -tags oracle -run Oracle -v ./internal/xsdre/` (env `YANGLINT` overrides the
binary). For each test pattern it generates `module x { leaf l { type string { pattern '…'; } } }`,
checks yanglint accepts the schema, then validates `{"x:l": candidate}` with `-t config` for the
table's match/nomatch strings, 36 probe strings and 12 seeded random strings. Candidates with
non-XML chars (e.g. `\v`, NUL) are excluded — libyang's JSON parser rejects them before the pattern
is consulted.

Run 2026-09-30: **schema verdicts 110/135 agree; match verdicts 3916/3988 agree (72 disagree);
RFC 7950 / RFC 6991 / RFC 9911 patterns: 1655/1655 agree.** Every disagreement was inspected;
none is an xsdre bug. They fall into:

| Class | Example | xsdre (XSD) | libyang |
|---|---|---|---|
| Class subtraction | `[a-z-[aeiou]]+` on `bcd` | match | no match (parsed as `[a-z-[aeiou]` then literal `]`); nested/`[\w-[\d]]`/`[a-[a]]` rejected at schema |
| Negated subtraction | `[^a-z-[0-9]]` | 31 diffs | same PCRE misparse |
| `\w` / `\W` | `_`, `€`, `+`, `$`, `^`, `😀` | XSD set | Perl `[\p{L}\p{N}_]` |
| `\s` / `\S` | U+00A0, U+2003 | not space | Unicode space |
| `.` | `\r` | no match | match |
| `\C` | `a` | no match (not NameChar) | PCRE `\C` = any single code unit |
| `\i \c \I`, `\P{IsX}`, supplementary / surrogate blocks | `\p{IsMathematicalAlphanumericSymbols}` | accepted | schema rejected |
| Block name prefix match | `\p{IsGreekExtended}` on `α` / `ἀ` | no / yes | yes / no (libyang `strncmp` finds `Greek` first) |
| `IsPrivateUse` planes 15/16 | U+F0000 | match | no match (BMP only) |
| Escaped `\^` | `\^` on `^` | match | no match (libyang turns `\^` into `\\^`) — also affects `\$`, which libyang accepts but can never match `$` |
| Invalid XSD accepted by PCRE | `(?:a)`, `a+?`, `\b`, `\$`, `\pL`, `{`, `a}`, `a{,3}`, `a{2`, `a{x}`, `[[]`, `[--a]`, `[a-c-e]`, `[a-z-[aeiou]x]` | ErrSyntax | accepted |
| Declared limit | `a{1001}`, `a{0,1001}`, `(a{100}){100}` | ErrUnsupported | accepted |

Consequence for Goal 2: on the IETF type library (the patterns real modules use) we agree 100 %.
The divergences are libyang deviations from XSD/RFC 7950 §9.4.5; they are recorded in
`conformance/deviations.md` as D-0002…D-0008 (our RE2 limits as U-0001). Rerun on the pinned
dev-container oracle (pcre2 10.46) gives identical numbers. The riskiest for real models are the
strict rejections (`\$`, `{` unescaped, `a{,n}`): a public model that libyang loads could fail in
ours. Before M2, scan the public-model corpus with `Compile` and decide per construct whether a
compatibility mode is warranted (it would be opt-in, never default).

## Tests

- `TestCases`: 93 patterns, 346 match/no-match assertions (RFC 7950 examples, RFC 6991 and RFC
  9911 `ietf-yang-types`/`ietf-inet-types` patterns copied verbatim, plus tricky cases).
- `TestErrors`: 39 invalid patterns → `ErrSyntax`, 6 → `ErrUnsupported`, all with a reason.
- Unicode version, XSD 1.0 block-name coverage, set algebra, category partition.
- `FuzzCompile`: 2 min / 9.7 M executions, no panic, every error typed.
